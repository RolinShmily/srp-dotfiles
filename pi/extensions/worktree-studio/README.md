# The Road Not Taken (worktree-studio MVP)

An opt-in Pi tool for comparing **two** plausible implementation approaches. It proposes an experiment only when the choice is genuinely unresolved; the tool itself asks permission before changing the filesystem. After confirmation, choose Pi subagents or multi-harness mode. Requires the `ask_user_question` extension and a dialog-capable Pi session (TUI or RPC with dialogs).

## Workflow

Load `pi/extensions/worktree-studio` together with `pi/extensions/ask-u-questions.ts` (the supported platform manifests include both). For a one-off session: `pi -e ./pi/extensions/worktree-studio -e ./pi/extensions/ask-u-questions.ts`.

1. The parent Pi supplies one goal and exactly two distinct approaches to `the_road_not_taken` (e.g. `{"goal":"Reduce API latency","routes":[{"name":"cache","approach":"Add per-request memoization"},{"name":"batch","approach":"Batch downstream reads"}]}`).
2. The tool asks whether to start, then whether to use Pi subagents or multi-harness. Pi mode asks whether to share the current model or select different ones from `ctx.modelRegistry.getAvailable()`. Multi-harness mode routes one alternative to `codex` and the other to `claude`; it checks both executables (and fails before creating worktrees if one is missing). Each CLI uses its own installed authentication and default model. In interactive mode, commands execute autonomously (`-a never` in Codex, `--permission-mode bypassPermissions` in Claude) while preserving workspace sandbox boundaries.
3. It refuses a dirty source repository, records `HEAD`, and creates two detached Git worktrees at `~/.pi/agent/worktree-studio/<run-id>/route-{a,b}`.
4. If tmux or Zellij is active, it starts one visible pane per route using native interactive TUIs: interactive Pi with the Studio worker bridge, Codex CLI with turn notifications, or Claude Code with Stop hooks. Completed workers remain open in their idle TUI so you can inspect full conversation/tool output and delegate follow-up tasks. The last 100 screen lines are saved as `<session>.screen.log`. Without a mux, it falls back to silent child processes and separate logs; `PI_WORKTREE_STUDIO_BACKEND=process` forces that fallback. Each route has its own prompt and a 15-minute default timeout (configurable up to 30).
5. On completion, it writes `manifest.json`, `report.md`, and tracked `.diff` files to the run directory, then steers the report location back to the parent Pi. External harnesses also record turn metadata, stderr logs, and event streams. The parent session can delegate follow-up tasks to either route via `action: "send"` (`route: "route-a" | "route-b"`, `task: "..."`), wait for the turn to complete, and update the report. When finished, call `action: "close"` to close the idle TUI panes. The parent must review the evidence; there is no automatic winner, merge, commit, or worktree deletion.

The tool accepts `action: "start"`, `"status"`, `"send"`, `"stop"`, and `"close"`. In mux mode, native TUIs remain open and idle after completing a turn. `send` dispatches a follow-up task to an existing route's TUI without restarting it. `stop` terminates running turns or active follow-ups. `close` terminates and closes the retained TUI panes once turns are idle. Pass `runId` to inspect, send to, or close an earlier experiment in the same session. Worktrees and files remain for inspection. A stopped session may not generate a final report if Pi exits before file writes finish.

## Boundaries

- A worktree is **not a security sandbox**: workers have the operating-system permissions and credentials of the invoking user. Do not use this tool on untrusted repositories without external isolation.
- The per-worker timeout is **not a token or spending limit**. A model can consume many tokens before the timeout; provider-reported cost may be zero when pricing data is missing. Review your provider's usage separately.
- Git worktrees do not carry ignored dependencies/build outputs (`node_modules`, `.venv`, etc.). The tool never installs dependencies or copies secret files automatically; tests may need a pre-provisioned environment.
- The source must be completely clean, including untracked files, because a `HEAD` snapshot otherwise cannot reproduce the user's working state.
- `report.md` separately lists untracked files: their contents are **not** part of the tracked `.diff`. Inspect them in the preserved worktree.
- Trusted projects are launched with `--approve`; untrusted projects with `--no-approve` (project-specific extensions/providers may therefore be unavailable). This controls project resource loading, **not** filesystem permissions.
- Reports, prompts, session files, and worktrees remain on disk. Process mode writes logs; mux mode displays live native TUIs, retains idle panes for follow-up delegation, and saves screen captures. When finished exploring, use `action: "close"` to close the panes. Review and remove files/worktrees manually when no longer needed; `close` never removes files.
- Multi-harness uses the static allowlist `codex` and `claude`. In both interactive mux mode and non-interactive process mode, permissions are fully opened as configured: Codex runs with `--sandbox danger-full-access` and `-a never`, and Claude runs with `--permission-mode bypassPermissions` (with a $0.50 budget in headless mode). In mux mode, native interactive TUIs stay open across turns for follow-up delegation. Check installed CLI versions before use. Selective integration remains out of scope.

You can check Pi extension loading with `pi --no-extensions -e ./pi/extensions/worktree-studio/index.ts --help`.
